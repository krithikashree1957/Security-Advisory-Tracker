## Design Principles

- **Beginner-friendly:** Only 2 tables, clear names, no complex joins.
- **Hackathon-focused:** Supports self-healing demo, KEV enrichment, and dashboard queries.
- **SQLite-compatible:** Uses standard SQLite types and features.
- **Deduplication at DB layer:** `cve_id` is unique to prevent duplicates automatically.

---

## 1. Tables Overview

| Table Name | Purpose | Why It Exists |
|------------|---------|---------------|
| `advisories` | Stores vulnerability advisory data from GitHub Advisories, enriched with CISA KEV status. | Core data table for the dashboard. All CVEs, severity, ecosystem, and KEV flags live here. |
| `scraper_runs` | Logs metadata about each scraper execution (timestamp, records fetched, fallback count, etc.). | Demonstrates self-healing behavior and scraper health to judges. |

**No foreign keys needed** — the tables are independent. `scraper_runs` is for logging, not relational integrity.

## 2. Table: `advisories`

### Purpose
Stores one row per unique CVE (vulnerability advisory). This is the main data source for the dashboard.

### Columns

| Column Name | Data Type | Required? | Description |
|-------------|-----------|-----------|-------------|
| `cve_id` | TEXT | **Required** | Unique identifier: either a CVE ID (e.g., `CVE-2024-12345`) or a GHSA ID (e.g., `GHSA-xxxx-yyyy-zzzz`) if no CVE has been assigned yet. Primary key. |
| `title` | TEXT | Optional | Short title or summary of the advisory. |
| `severity` | TEXT | **Required** | Severity level: `CRITICAL`, `HIGH`, `MEDIUM`, `LOW`, or `UNKNOWN`. |
| `ecosystem` | TEXT | **Required** | Package ecosystem (e.g., `npm`, `PyPI`, `Go`, `Maven`). |
| `affected_package` | TEXT | **Required** | Name of the affected package (e.g., `lodash`, `requests`). |
| `source` | TEXT | **Required** | Data source: `GITHUB_ADVISORY` (or `NVD` if you add it later). |
| `in_cisa_kev` | INTEGER | **Required** | Boolean flag: `1` if in CISA KEV (actively exploited), `0` otherwise. |
| `published_at` | TEXT | Optional | Publication date from the advisory (ISO 8601 string, e.g., `2024-08-15T10:30:00Z`). |
| `advisory_url` | TEXT | **Required** | Link to the original advisory (e.g., `https://github.com/advisories/...`). |
| `extraction_method` | TEXT | Optional | How the CVE was extracted: `primary`, `fallback`, or `failed`. For self-healing demo. |
| `created_at` | TEXT | **Required** | Timestamp when the row was inserted (auto-generated by SQLite). |
| `updated_at` | TEXT | Optional | Timestamp when the row was last updated (auto-generated on UPSERT). |

### Keys

- **Primary Key:** `cve_id` (ensures no duplicate CVEs)
- **Foreign Keys:** None

### Indexes

| Index Name | Column(s) | Why |
|------------|-----------|-----|
| `idx_severity` | `severity` | Fast filtering by severity in the dashboard. |
| `idx_kev` | `in_cisa_kev` | Fast query for "Patch Now" section (KEV-flagged items). |
| `idx_ecosystem` | `ecosystem` | Fast filtering by ecosystem (e.g., show only `npm` advisories). |

## 3. Table: `scraper_runs`

### Purpose
Logs each scraper execution for transparency and demo purposes. Shows judges that you're tracking fallback usage and scraper health.

### Columns

| Column Name | Data Type | Required? | Description |
|-------------|-----------|-----------|-------------|
| `run_id` | INTEGER | **Required** | Auto-incrementing ID. Primary key. |
| `timestamp` | TEXT | **Required** | When the scraper run started (ISO 8601 string). |
| `source` | TEXT | **Required** | Data source: `GITHUB_ADVISORY` (or `CISA_KEV` if you log separately). |
| `records_fetched` | INTEGER | **Required** | Total number of advisories fetched in this run. |
| `fallback_count` | INTEGER | **Required** | Number of fields extracted using fallback logic. |
| `failure_count` | INTEGER | **Required** | Number of fields that failed entirely (both primary and fallback). |

### Keys

- **Primary Key:** `run_id`
- **Foreign Keys:** None

### Indexes

| Index Name | Column(s) | Why |
|------------|-----------|-----|
| `idx_timestamp` | `timestamp` | Fast query for "last run time" and historical trends (if added later). |

## 4. Relationships

- **No foreign keys** between tables.
- `advisories` is standalone — each row is a unique CVE.
- `scraper_runs` is a log table — independent of `advisories`.
- The dashboard queries both tables separately:
  - `advisories` for the main table and charts.
  - `scraper_runs` for the "Scraper Health" panel.

### `advisories` Table

**Required (NOT NULL):**
- `cve_id`
- `severity`
- `ecosystem`
- `affected_package`
- `source`
- `in_cisa_kev`

- `title`
- `published_at`

- `updated_at`

### `scraper_runs` Table

## 6. SQL Schema (SQLite)

```sql
-- Table: advisories
CREATE TABLE IF NOT EXISTS advisories (
    cve_id TEXT PRIMARY KEY,
    title TEXT,
    severity TEXT NOT NULL,
    ecosystem TEXT NOT NULL,
    affected_package TEXT NOT NULL,
    source TEXT NOT NULL,
    in_cisa_kev INTEGER NOT NULL DEFAULT 0,
    published_at TEXT,
    advisory_url TEXT NOT NULL,
    extraction_method TEXT,
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT DEFAULT (datetime('now'))
);

-- Indexes for advisories
CREATE INDEX IF NOT EXISTS idx_severity ON advisories(severity);
CREATE INDEX IF NOT EXISTS idx_kev ON advisories(in_cisa_kev);
CREATE INDEX IF NOT EXISTS idx_ecosystem ON advisories(ecosystem);

-- Table: scraper_runs
CREATE TABLE IF NOT EXISTS scraper_runs (
    run_id INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp TEXT NOT NULL,
    source TEXT NOT NULL,
    records_fetched INTEGER NOT NULL,
    fallback_count INTEGER NOT NULL,
    failure_count INTEGER NOT NULL
);

-- Index for scraper_runs
CREATE INDEX IF NOT EXISTS idx_timestamp ON scraper_runs(timestamp);
```

## 7. UPSERT Behavior

When inserting advisories, the system uses SQLite's `ON CONFLICT(cve_id) DO UPDATE` syntax to:

- Insert new CVEs normally.
- Update existing CVEs if their KEV status changes (e.g., `in_cisa_kev` changes from 0 to 1).
- Update `extraction_method` and `updated_at` on every re-scrape.

This ensures the database stays current even if CISA adds a CVE to the KEV list after the initial scrape.

**Example UPSERT statement:**

```sql
INSERT INTO advisories (
    cve_id, title, severity, ecosystem, affected_package,
    source, in_cisa_kev, published_at, advisory_url, extraction_method
) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
ON CONFLICT(cve_id) DO UPDATE SET
    in_cisa_kev = excluded.in_cisa_kev,
    extraction_method = excluded.extraction_method,
    updated_at = CURRENT_TIMESTAMP;
```

---

## 8. GHSA ID Fallback Handling

Some GitHub Advisories may not have an assigned CVE ID immediately (they will only have a GHSA ID like `GHSA-xxxx-yyyy-zzzz`). 

**Pipeline behavior:**
- If a CVE ID is present, use it as `cve_id`.
- If no CVE ID is present, fall back to using the GHSA ID as `cve_id`.
- This ensures no advisory records are dropped due to missing CVE IDs.

**Example:**
- Advisory with CVE: `cve_id = "CVE-2024-12345"`
- Advisory without CVE: `cve_id = "GHSA-xxxx-yyyy-zzzz"`

Both are valid primary keys in the `advisories` table.

---

## 9. Why This Design Works for a Hackathon

1. **Two tables only** — easy to understand, explain, and maintain.
2. **Deduplication is automatic** — `cve_id TEXT PRIMARY KEY` prevents duplicates.
3. **Self-healing is visible** — `extraction_method` and `scraper_runs` table prove fallback usage.
4. **Dashboard queries are fast** — indexes on `severity`, `in_cisa_kev`, and `ecosystem`.
5. **No complex relationships** — no foreign keys, no joins, no ORM needed.
6. **SQLite-friendly** — uses standard types, no advanced features.
7. **Handles real-world edge cases** — GHSA ID fallback and KEV status updates via UPSERT.

## 10. How to Use in Code

### Insert/Update an Advisory (UPSERT)

```python
import sqlite3

conn = sqlite3.connect("data/advisories.db")
cursor = conn.cursor()

cursor.execute("""
    INSERT INTO advisories (
        cve_id, title, severity, ecosystem, affected_package,
        source, in_cisa_kev, published_at, advisory_url, extraction_method
    ) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
    ON CONFLICT(cve_id) DO UPDATE SET
        in_cisa_kev = excluded.in_cisa_kev,
        extraction_method = excluded.extraction_method,
        updated_at = CURRENT_TIMESTAMP
""", (
    "CVE-2024-12345",
    "Remote Code Execution in lodash",
    "CRITICAL",
    "npm",
    "lodash",
    "GITHUB_ADVISORY",
    1,  # in_cisa_kev
    "2024-08-10T14:20:00Z",
    "https://github.com/advisories/GHSA-xxxx",
    "primary"
))

conn.commit()
conn.close()
```

### GHSA ID Fallback in Python

```python
def extract_cve_id(record):
    """
    Extract CVE ID from a record, falling back to GHSA ID if no CVE is assigned.
    """
    cve_id = record.get("cve_id") or record.get("cve_ids", [None])[0]
    
    # Fallback to GHSA ID if no CVE ID
    if not cve_id:
        cve_id = record.get("ghsa_id")  # e.g., "GHSA-xxxx-yyyy-zzzz"
    
    return cve_id
```

```python
cursor.execute("""
    SELECT cve_id, title, severity, ecosystem, affected_package, advisory_url
    FROM advisories
    WHERE in_cisa_kev = 1
    ORDER BY severity DESC
""")
```
